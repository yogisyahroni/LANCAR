# Evidence — ECON-2026-002

## Acceptance Criteria Source

Original checklist from `task-food-marketplace-parity-2026.md`:

- `[ ]` Supply defined from truly available/capable couriers, not all registered accounts.
- `[ ]` Demand defined by service/zone/time window with event freshness.
- `[ ]` Metrics include match time, acceptance, no-supply, idle time and ETA.
- `[ ]` Delayed data has staleness indicator and cannot drive extreme pricing silently.

## Scope Implemented

- Extended the existing order-service surge input contract with service/zone dimensions, rolling demand window, lifecycle event age/freshness, available and idle capable courier counts, acceptance rate, match time, no-supply count, idle time, and ETA.
- Replaced the old zone-only supply count with a service-aware query restricted to verified/online couriers assigned to the zone, matching service capability, and `idle` availability state. Busy states are excluded; a missing state row follows the existing availability policy and is treated as idle.
- Grouped demand by canonical service code, pickup zone, and a 15-minute rolling window. `order_events` provide searching/accepted/no-supply counts and lifecycle freshness; match time uses persisted `assigned_at - created_at`.
- Persisted aggregate snapshots at `marketplace_metrics:<zone_id>:<service_code>` with a ten-minute TTL. Existing zone/global multiplier keys remain compatible and use the highest service multiplier per zone.
- Made stale lifecycle data explicit and fail-closed for demand-based surge increments while retaining the configured ceiling for existing provider multipliers.
