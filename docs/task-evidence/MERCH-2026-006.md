## Scope Implemented

- Added a versioned `merchant_quality_policies` control-plane table with
  configurable window, minimum order volume, component weights, per-surface
  thresholds, effective dates, and explicit `apply_to_search`/
  `apply_to_ads` switches. The seeded v1 policy leaves both gates disabled to
  preserve current discovery behavior until an operator enables the policy.
- Added authoritative live score calculation from food order acceptance and
  timeout, prep accuracy, item availability, customer review, merchant-
  attributable refund/cancel, and confirmed safety/policy review facts. The
  API persists each result as an immutable scorecard snapshot with policy
  version, window, component scores, and evidence counts.
- Connected catalog moderation rejection/approval to reviewed policy input
  events. Only confirmed events affect the safety/policy component.
- Added merchant score and appeal endpoints in the existing merchant/report
  bounded module. Merchant owner/staff scope is enforced for reads/submits;
  admin/support review requires an allow-listed role, step-up authentication,
  decision note for terminal outcomes, and persists reviewer identity/role.
- Updated food discovery's organic and sponsored paths to call the same
  database-authoritative `merchant_quality_is_eligible` function. A gate is
  therefore possible only when the explicit policy enables that surface.
