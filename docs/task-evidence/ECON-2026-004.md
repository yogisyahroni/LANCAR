## Scope Implemented

- Added a versioned `CourierEarningPolicy` and `CourierEarningComponents` contract. Service metadata may override the policy per service code while the shared calculation remains one implementation.
- Settlement snapshots now persist the earning policy and initial earning components, including base earning, waiting, toll, return, extra-service, cancellation, penalty, and estimated total fields.
- Courier offer responses, realtime events, push notification metadata, and normalized mobile order responses expose the server-generated policy and earning components before acceptance. Legacy orders receive a deterministic safe fallback.
- Added server-owned order-leg facts for verified toll reimbursement, return compensation, extra-service compensation, cancellation compensation, policy snapshot, and component snapshot. Existing idle compensation is represented as waiting compensation.
- Updated the append-only delivery earning trigger and POD credit path to use the persisted component snapshot, apply per-component caps, subtract penalties, and retain policy/components in ledger metadata. Client-computed amounts are not read for the credit.
- Kept the existing single delivery ledger uniqueness/advisory lock boundary for replay safety and did not create a second payout source of truth.
