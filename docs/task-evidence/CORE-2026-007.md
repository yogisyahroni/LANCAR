## Scope Implemented

- Added `event_version` and optional authoritative `state_version` fields to order events. Polling responses receive a deterministic event cursor derived from the server event timestamp, while realtime frames are normalized at the WebSocket boundary for legacy producers.
- Added server-side duplicate delivery suppression when a client belongs to both order and user rooms.
- Added frontend stale-event guard and an `onResync` hook. The Socket.IO client exposes an order-update signal whose consumer must fetch the authoritative snapshot instead of applying a socket payload as a state patch.
- Added customer and courier per-order version guards. Every socket connect/reconnect schedules an online-only WorkManager sync; customer refreshes order history and courier replays only its existing idempotent status/scan/PoD queue.
- Existing courier mutations retain deterministic idempotency keys and explicit conflict handling; no unsafe offline mutation was introduced.
