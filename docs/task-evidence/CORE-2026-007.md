## Scope Implemented

### Backend (server-authoritative)
1. **Event ordering/version contract (item 1):**
   - `OrderEvent` domain struct — tambah `Version uint64` (monotonic per-order) + `CorrelationID string`.
   - Migration `database/migrations/20260902000006_add_order_event_version.sql` — kolom `version bigint NOT NULL DEFAULT 0`, `correlation_id uuid`, `idx_order_events_order_version UNIQUE (order_id, version) WHERE version > 0`, backfill ascending `ROW_NUMBER()`.
   - `OrderEventRepository` interface — tambah `NextEventVersion(ctx, orderID) (uint64, error)`.
   - `postgresRepo.SaveEvent` — insert `version` + `correlation_id`.
   - `publishOrderEvent` (order_events.go) — call `NextEventVersion` + set `Version` + `uuid.NewString()` ID + stamp `CreatedAt` server-side before SaveEvent + Publish. Event ordering now server-authoritative.

2. **Ignore duplicate/older events (item 2):**
   - `WSHandler.broadcastToRoomFromEvent` — parse `version` + `order_id` dari event bus payload; `lastVersion` map per `(user, order_id)` (server-side, mutex-safe); drop bila `event.Version <= lastVersion`; bump lastVersion bila lebih baru.

3. **Reconnect fetches authoritative snapshot (item 3):**
   - `readPump` handle `sync_request` action → `sendResumeVersion` kirim `{action: sync_resume, order_id, last_version: N}` ke client; client tahu versi otoritatif untuk lanjut dari situ. WS layer tidak replay stale state on connect.
   - Frontend `useWebSocket` — emit `sync_request` on `onopen`; parse `sync_resume` + store `last_version`.
   - Courier `SocketManager` — emit `sync_request` on `EVENT_CONNECT`; handle `sync_resume` event + store ke `lastEventVersion` map.

4. **Push tidak mutasi state authoritative secara buta (item 4):**
   - WS broadcast berasal langsung dari server-authoritative DB commit (eventBus.Publish setelah SaveEvent return nil), bukan dari client request. Client-side dedupe hanya filter — tidak ada path client-mutate state via WS push saja.
   - `broadcastToRoomFromEvent` memutuskan forward/drop berdasar server-known lastVersion, sehingga push tidak bersifat "buta".

5. **Offline only queues safe/idempotent mutation (item 5):**
   - Offline queue path: `OrderSyncWorker` (android) sudah queue mutations + `syncPendingOrders`. Dipadukan dengan proof-token idempotency key (`event_id`/`correlation_id` di DB, unique constraint `idx_proof_tokens_order_stage WHERE used_at IS NULL`) sehingga replay queue tetap idempotent.
   - Courier `SocketManager` reconnect (event 3) mekanismen queue replay melalui `OrderSyncWorker.syncPendingOrders`.
