# Evidence — ADMEXP-2026-004

## Acceptance Criteria Source

The original checklist in `task-food-marketplace-parity-2026.md` requires:

- Admin can filter by country/market, city/zone, surface, locale and app version.
- The overview clearly separates `LIVE`, `SCHEDULED`, `CANARY`, `DRAFT`, `AWAITING_APPROVAL`, `ROLLED_BACK` and `EXPIRED`.
- The overview links directly to an offending revision, campaign or asset rather than showing only aggregate errors.
- A global overview never implies that one market configuration is active everywhere.

## Scope Implemented

- Added the App Experience operational cockpit at `/app-experience/overview` while retaining the existing bounded Admin Experience page and API ownership.
- Added explicit market, city, zone, surface, locale and app-version controls with a visible selected-scope banner. City/zone targeting retains broad fallback behavior; locale matching is normalized and app-version matching is semver/range aware.
- Added live, scheduled, canary, draft, awaiting-approval, rolled-back, expired and kill-switched state presentation, plus scheduled/expiring/canary/kill-switch/approval metrics.
- Added latest publish/rollback actor and timestamp from the existing audit API.
- Added 24-hour fetch/render health using the existing observability API, scoped by market, surface and app version, including cache, parse/schema/render, broken-asset and deep-link counters.
- Added unsupported app-version distribution warnings and actionable schema, asset, deep-link and runtime warning links.
- Added revision and asset focus state to the existing revision/editor UI so overview links visibly identify the offending target.
- Added the server-side city/zone/locale/app-version manifest filters and surface-scoped observability filter; no duplicate store or migration was created.
