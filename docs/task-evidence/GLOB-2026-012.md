# Evidence — GLOB-2026-012

## Acceptance Criteria Source

The original checklist in `task-food-marketplace-parity-2026.md` requires:

- Core UI uses localization keys, not hardcoded Indonesian/English strings.
- Date/time/timezone/currency/number/address/phone formatting is locale aware.
- Layout is tested for long translations and RTL before entering RTL markets.
- Dynamic marketing content supports locale fallback chain.
- Critical legal/financial copy is versioned and market approved.
- Accessibility baseline remains valid after dynamic content/localization.

## Scope Implemented

- Added typed `id-ID`/`en-US` web dictionaries, deterministic regional fallback, locale cookie persistence, document `lang`/`dir`, accessible locale switching and localized core landing, auth, portal and order/payment UI.
- Added shared web number, currency, date, time, date-time, address and phone formatters, with locale-aware route preview labels and map locale parameters.
- Added Android locale contracts and runtime application for customer, courier and merchant apps, including canonical locale tags, fallback, RTL `LocalLayoutDirection`, locale-aware formatters and migrated core history/inbox/settlement presentation.
- Added dynamic marketing resolution with regional/language/market fallback and publication/effective-window checks. Added legal resolution that requires approval metadata and preserves document version/effective URI from the existing market-config public contract.
- Added translation governance and localization guidelines covering long-copy, RTL, accessibility, market approval and key lifecycle.
- Fixed core login contrast regressions surfaced by accessibility testing and added localization contract validation to the Android workflow.

## Files Changed

- `frontend/src/i18n/` — typed dictionaries, locale configuration, formatters, content resolution, server locale lookup and unit tests.
- `frontend/src/components/i18n/` — provider, locale switcher and approved/legal content link.
- `frontend/src/app/`, `frontend/src/components/landing/`, `frontend/src/components/orders/` — localized core web flows and formatting.
- `frontend/e2e/localization.spec.ts` — public ID/EN, RTL overflow and long-copy browser checks.
- `frontend/src/tests/unit/OrderSummary.test.tsx`, `frontend/src/tests/unit/PaymentModal.test.tsx` — provider-aware unit fixtures.
- `android-app-customer/`, `android-app/`, `android-app-merchant/` — locale contracts/runtime wiring, locale-aware core presentation, resource locale tags and targeted contract tests.
- `docs/product/localization-guidelines.md`, `docs/product/translation-key-governance.md` — product and governance rules.
- `scripts/mobile/check_localization.py`, `.github/workflows/android-apps.yml` — deterministic cross-platform localization contract check and CI wiring.

The existing `backend/admin-service` market-config contract was reused rather than duplicated: its legal-document schema carries locale/version/status/effective time, and its public projection only exposes approved documents effective at request time.
