# Evidence — TOW-2026-004

## Scope Implemented

- The courier towing flow now requires an inspection photo before leaving pickup, a loading photo before the transit action can advance the order, and an unloading photo before opening completion/signature.
- Loading and unloading proof URLs are retained in the service-report draft store and included in the towing report request. Successful completion clears those draft proof values.
- The order-service validates before-condition, loading, unloading, completion-photo, signature, and completion timestamp before calling the repository. Missing loading or unloading proof is rejected as `ERR_INVALID_SERVICE_REPORT` input.
- Existing `towing_reports` columns are used for loading/unloading proof persistence, keeping the data real and traceable rather than adding placeholder values.
