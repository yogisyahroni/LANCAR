# Evidence — AGG-2026-001

## Scope Implemented

- Removed hardcoded provider and city fallback data from `AggregatorWizard`
  and `AggregatorForm`.
- Provider selection now consumes the authenticated backend provider catalog
  and filters to providers declaring tariff and shipment capabilities.
- Removed the unconditional `CGK` origin default. Pickup and destination
  provider codes are explicit fields and are sent through the canonical tariff
  route; no fabricated city label is shown.
- Enforced a pickup coordinate for the wizard before proceeding, so a pickup
  cannot be represented as a text-only successful location.
- Added order-service/API-gateway catalog proxy wiring without exposing
  provider credentials.

## Files Changed

- `frontend/src/types/logistics.ts` — provider/location API types.
- `frontend/src/hooks/useLogisticsProviders.ts` — backend-only provider catalog hook.
- `frontend/src/components/orders/AggregatorWizard.tsx` — remove CGK/mock data,
  require explicit provider location input, and use catalog providers.
- `frontend/src/components/orders/AggregatorForm.tsx` — remove provider/city
  fallback and use catalog providers/provider codes.
- `frontend/src/components/orders/AddressPicker.tsx` — route reverse-geocode
  requests through the backend maps endpoint.
- `backend/order-service/internal/domain/payment_link.go` — optional provider
  catalog port and credential-free descriptor.
- `backend/order-service/internal/infrastructure/integration_gateway_client.go` —
  catalog client.
- `backend/order-service/internal/service/payment_link_service.go` — catalog
  delegation.
- `backend/order-service/internal/handler/payment_link_handler.go` — catalog
  endpoint.
- `backend/order-service/cmd/api/main.go` — authenticated catalog route.
- `backend/api-gateway/src/index.ts` — order-service proxy for `/logistics`.
