## Scope Implemented

- Added a shared `PricingBreakdown` contract with explicit component kinds for customer charges/discounts/adjustments, merchant gross/commission/subsidy, and courier earning.
- Added pure recalculation and validation of customer total, merchant payable, courier earning, and platform residual; invalid or tampered snapshots are rejected by validation.
- Integrated the breakdown into parcel quotes and Food quotes. The existing Redis quote envelope and order `pricing_snapshot` now retain the resolved policy version, components, stakeholder totals, and labels.
- Loaded settlement percentages from the existing `delivery_service_products` policy columns with bounded server-side fallbacks. No client amount is used for the calculation.
- Added market-aware label resolution through `pricing_component_labels_<market>` with a stable default config and stable financial component codes.
- Added migration `20260907000012_canonical_marketplace_pricing_policy.sql` and the public contract `docs/contracts/marketplace-pricing-2026.md`.

### Integration and persistence

The quote response contains `PricingBreakdown`; the stored `PricingEstimateResponse` contains the same breakdown before `SaveEstimate`; Food order creation marshals the quote response into the existing `orders.pricing_snapshot`; parcel order creation marshals the stored pricing estimate into the same snapshot field. ### Client boundary

The existing client flow submits quote identity/fingerprint and displays server totals. This implementation does not add client fee arithmetic; all new component amounts are calculated from server menu, service-product, configuration, and quote inputs.
