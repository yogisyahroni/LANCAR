## Scope Implemented

- Android customer create-order, payment-session, and payment-confirm requests
  now carry stable `X-Idempotency-Key` values across retries. The booking and
  payment view models reuse the key for the same operation.
- Matching now takes the persisted quote/order contract, intersects Redis
  proximity candidates with the DB capability/vehicle/radius/online query, and
  filters availability states to idle or the documented safe conditional path.
- Matching triggers use a Redis distributed lock and status guards so replayed
  payment callbacks do not launch duplicate searches.
- Courier acceptance uses a row lock and a status predicate. The first courier
  atomically wins; subsequent accepts are mapped to HTTP 409 without assigning
  the order again.
- No-supply keeps the existing configured radius expansion, offer-batch expiry,
  retry endpoint, no-courier event, and cancellable order state.
- Leg-fee payout creation first resolves an existing record and is backed by a
  unique `order_leg_id` index for concurrent completion/reassign retries.
