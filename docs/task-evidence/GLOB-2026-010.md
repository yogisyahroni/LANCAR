## Acceptance Criteria Source

## Scope Implemented

- Evolved the existing `admin-service` support/operations boundary instead of creating a duplicate microservice. This preserves the repository's bounded ownership for admin, exception and dispute workflows.
- Added durable `support_cases`, `support_case_links`, `support_case_events` and `support_case_actions` schema. Links preserve references to authoritative aggregates; order/payment state is resolved at action/read time.
- Added versioned support policy for service, market, case state, order state, payment state and actor role.
- Added authenticated customer/merchant/courier intake and actor-scoped reads, plus staff queue, assignment, SLA, escalation, resolve and reopen operations.
- Added idempotent support actions. Refund/compensation actions require finance role + TOTP, write a processing record before calling the audited order-service refund API, pass an idempotency key, and record only a redacted success/failure result after the audited API responds.
- Added gateway auth/proxy wiring and admin dashboard Cases page with append-only timeline. Sensitive payment/proof links are role restricted and idempotency keys are never returned.
