# Evidence — ADMEXP-2026-018

## Acceptance Criteria Source

The original checklist in `task-food-marketplace-parity-2026.md` requires:

- Inventory current banner/promo/feature-flag persistence and API ownership before creating new tables/services.
- Reuse existing proven primitives where semantics match.
- Define which existing data migrates into Experience Service and which remains authoritative in Promo/business service.
- Keep promo financial rule/eligibility in the Promo/Pricing domain while Experience controls only presentation/exposure.
- Consolidate or bridge runtime feature flags so the UI does not write two independent flag stores.
- Deprecate/redirect the old direct-write route/page only after migration/backfill and compatibility tests pass.
- Prevent two admin screens from publishing conflicting live banner/service visibility truth without deterministic precedence.

## Scope Implemented

- Added the source-of-truth contract documenting existing tables, APIs, UI ownership, migration boundary and domain separation.
- Added an idempotent PostgreSQL backfill that aggregates active `global_banners` into one deterministic `customer_android` manifest per configured market, preserving priority order and recording source IDs in append-only audit metadata.
- Reused the existing Experience manifest revision/audit store, existing Promo/Pricing tables and engine, and existing feature-flag store/API; no duplicate service or persistence source was introduced.
- Kept promo economics out of Experience manifest properties. Promo eligibility, discount, budget and settlement remain owned by `promoEngine.ts` and the existing promo/business tables.
- Replaced the legacy dashboard banner page with a redirect-compatible component and redirected `/banners` and `/feature-flags` to the canonical App Experience routes.
- Disabled legacy Admin banner POST/PATCH/DELETE writes with a typed `410 LEGACY_BANNER_WRITE_DISABLED` response. Read endpoints remain as compatibility fallback only.
- Preserved deterministic Android precedence: the legacy global banner is rendered only when the resolved Experience manifest has no safe sections.
