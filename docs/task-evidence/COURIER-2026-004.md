# Evidence — COURIER-2026-004

## Acceptance Criteria Source

- `[x]` Online state separate from active-job state.
- `[x]` Stale heartbeat/location transitions courier to unavailable by policy.

## Scope Implemented

- Extended the existing `courier_availability_state` source of truth with
  explicit presence state, reason, heartbeat, and transition timestamps. The
  existing active-work state remains separate and the snapshot view derives
  current work from active order legs.
- Added PostgreSQL effective-presence and matchability policy functions plus a
  stale transition function. Missing/stale location or heartbeat makes an
  online courier unavailable; a fresh accepted location recovers only an
  automatic stale transition, while manual offline/break/limited states are
  preserved.
- Added the admin-service policy worker that persists stale transitions and
  emits structured transition/error/startup logs.
- Updated duty/profile/tracking payloads and matching/broadcast/offer paths to
  consume the server-authoritative presence policy. Offer acceptance now uses a
  per-courier transaction advisory lock before active-job evaluation and keeps
  the existing profile row lock, preventing concurrent incompatible accepts.
- Updated Android models and courier surfaces to display explicit presence/work
  state, block new offers until a server snapshot has been recovered, and keep
  acceptance intents durable across process/network loss. Pending acceptance
  intents replay through the guarded repository path with a stable idempotency
  key instead of being sent as a generic status update.
