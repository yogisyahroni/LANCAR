# Evidence — ADMEXP-2026-010

## Acceptance Criteria Source

The original checklist in `task-food-marketplace-parity-2026.md` requires:

- [x] Oversized/unsupported/corrupt files rejected before becoming publishable.
- [x] Admin cannot delete an asset still referenced by live or retained rollback revision.
- [x] Asset replacement creates a new immutable version/reference; do not silently mutate historical campaign content.
- [x] CDN/object-storage credential never reaches browser.
- [x] Asset upload and publish are separately permissioned where appropriate.

The task also requires the Admin experience to support approved image/animation references, preview, internal label, delivery metadata, compatibility hints, low-bandwidth fallback, usage references and lifecycle visibility.

## Scope Implemented

- Added a real Asset Library view to the existing App Experience route. It reads the canonical `/admin/experience/assets` and `/admin/experience/revisions` APIs and derives deduplicated immutable asset versions plus live, draft, superseded and rolled-back usage references.
- Added local file preflight for approved image/animation/video media. It rejects unsupported MIME types, files over 5 MiB and corrupt/un-decodable media before the reference can be validated; it computes SHA-256 and displays actual preflight filesize and dimensions.
- Added server validation through the existing `POST /admin/experience/assets` route. The existing strict schema enforces HTTPS or `/assets/` URI safety, MIME allowlist, dimensions, checksum, maximum declared size, version, expiry/retention and fallback compatibility before a draft can be published.
- Added remote/local asset preview, internal label (`asset_id`), content type, dimensions, declared size limit, checksum, expiry, retention, cache policy and low-bandwidth fallback fields.
- Added surface/placement compatibility hints derived from the manifest sections that reference each asset, plus usage cards for live, draft and retained historical revisions.
- Added derived lifecycle labels: active, deprecated and scheduled deletion. There is intentionally no destructive delete control; live/retained references remain protected and replacement is represented by a new immutable version in a new manifest revision.
- Kept upload/reference validation and campaign publication separate. The page requires `experience.asset.write` for validation, while existing manifest publication remains protected by `experience.publish`. The contract continues to treat the actual CDN/object-storage upload as an external publishing-side action, so no bucket credential or upload token is sent to the browser.
