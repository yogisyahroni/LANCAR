# Evidence — ECON-2026-006

## Acceptance Criteria Source

Original checklist from `task-food-marketplace-parity-2026.md`:

- `[ ]` Commission/fee contract versioned by merchant/market/service/effective date.
- `[ ]` Food order settlement stores applied commercial terms.
- `[ ]` Ads spend remains separate from commission.
- `[ ]` Manual commercial override requires approved contract/reference and audit.
- `[ ]` Historical orders never reprice when merchant contract changes later.

## Scope Implemented

- Added `merchant_commission_contracts` with merchant, market, service, version, effective range, commission basis/rate/fixed fee, approval fields, status, and metadata.
- Database validation rejects approved contracts without approver/reference and rejects overlapping approved effective ranges for the same merchant lane.
- A BEFORE INSERT order trigger resolves the approved contract using the order merchant, market from the server pricing snapshot, service, and order creation time. It stores `merchant_commercial_terms` and the calculated commission in `orders.settlement_snapshot`; later contract changes do not touch that snapshot.
- A marked service-default fallback keeps legacy merchants operable while making the source explicit. Ads spend is represented separately as `ads_spend_idr: 0` and is never folded into commission.
- Food settlement reads the frozen commercial snapshot, uses the frozen commission amount for merchant payout/ledger, and copies the full terms into `merchant_settlements.metadata`.
- Added Admin list/create/approve/retire endpoints. Creation is draft-only; approval requires finance role, TOTP, idempotency scope, approval reference, and an audit row.
