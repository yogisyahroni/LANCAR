## Scope Implemented

- Added `evaluateOnDemandDeliveryRecovery` as the server policy boundary. It validates reason codes, requires field evidence, keeps a custody-aware settlement guard, and only adds return/cancel when explicitly allowed.
- `failed_delivery` courier reports now require an owned on-demand order, an approved reason code, and a secure photo. The response includes recovery options and incident id; the server writes structured evidence to `courier_safety_events` and `order_events` without mutating the order to a terminal failed/return state.
- Android courier issue reporting now sends the selected reason code alongside the photo and deliberately opens the evidence dialog from the failed-delivery action.
- Customer web/Android actions now expose help/report/claim language for the on-demand flow. Customer claims remain in LANCAR's internal disputes system and their order audit event links the latest failed-delivery incident when available.
- Existing proof requirements, geofence/PIN/signature/photo checks, recipient handoff safeguards, and settlement gating were retained and covered by the existing courier contract/proof implementation.
