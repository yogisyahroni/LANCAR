# Evidence — ICON-2026-002

## Acceptance Criteria Source

- Service icon semantics are consistent across dashboard, order creation, history/detail and empty states.
- Aggregator and Towing do not reuse the same generic truck icon where context could be confused.
- Marketing illustration assets do not replace accessible functional icons and visible labels in transactional navigation.

## Scope Implemented

- Added `frontend/src/components/orders/serviceIcon.ts` as the shared canonical mapping.
- Mapped Paket/Instant to `Package`, Food to `UtensilsCrossed`, Tambal Ban to `Wrench`, Towing to `CarFront`, Aggregator to `Truck`, and unknown metadata to `CircleHelp`.
- Reused the mapping from Customer landing service cards, Dashboard active orders and `OrderServiceBadge`; legacy server model values (`instant`, `food`, `towing`, `tambal_ban`) resolve to the same canonical presentation.
- Kept service labels visible and decorative icon SVGs `aria-hidden` where text already names the service.
