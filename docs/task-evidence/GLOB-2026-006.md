Original checklist from `task-food-marketplace-parity-2026.md`:

- `[x]` Dispatch candidate scoring can consider ETA, distance, vehicle/capability, workload, acceptance probability, completion probability and marketplace constraints.
- `[x]` Food matching can combine merchant prep readiness, courier arrival prediction, waiting risk and batching compatibility.

These are the original requirements. Staging and live courier/provider behavior are recorded separately as release follow-up.

## Scope Implemented

- Added a versioned deterministic dispatch policy with configurable weights and limits, while preserving the existing order-service ownership boundary.
- Added candidate scoring for ETA, distance, vehicle fit, capability fit, workload, acceptance, completion, reliability, food readiness, batching, and service-product constraints.
- Added an ETA prediction value object with source/confidence/model metadata. It never writes or changes authoritative order status.
- Added food matching signals for merchant readiness, predicted courier arrival, waiting risk, readiness alignment, and batching compatibility.
- Added optional model injection with validation and deterministic fallback for missing, failed, or invalid model responses. Fallbacks are safe and do not change order state.
- Added structured decision logs and governed `dispatch.decision` canonical events. Audit payloads use a one-way candidate hash and include rank, score breakdown, ETA, confidence, fallback state, and model/rule versions.
- Added product-backed vehicle, batching, and maximum-ETA constraints; dispatch stats now include completion rate and vehicle type.
- Added finite coordinate/route-metric validation at the existing maps repository boundary.
- Added migration-backed policy defaults with rollback support and registered the event schema in datalake-worker.
