## Scope Implemented

- Added a migration-backed canonical merchant onboarding lifecycle with typed legal profile, owner/operator, market, payout reference, market-scoped document requirements, review history, transition guard, and fail-closed activation gate.
- Preserved the existing bank-account fields and `merchant_commission_contracts` as their respective sources of truth; no duplicate financial or commercial store was introduced.
- Registration creates `SUBMITTED` applications. A `DRAFT`/`REJECTED` application can resubmit through the existing Merchant API with the same merchant ID; the service cannot self-activate.
- Admin review now uses privileged, TOTP-protected, idempotent lifecycle endpoints for verification, activation, rejection, suspension, and market requirement administration. Transitions and manual requirement changes are audited.
- Admin merchant review UI shows lifecycle, market requirements/document presence, legal/payout summary, and the active commercial contract version/effective date.
- Merchant Android model consumes canonical `onboarding_status` while retaining a safe fallback for older responses that omit the new field.
- Added the API/state contract at `docs/contracts/merchant-onboarding-2026.md`.
