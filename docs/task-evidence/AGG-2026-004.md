# Evidence — AGG-2026-004

## Scope Implemented

- Replaced the manual aggregator success delay and unconditional success
  navigation with the authenticated persisted customer-order mutation.
- Builds the create payload from the selected server tariff, resolved pickup
  and dropoff coordinates, recipient/package facts, provider, native service
  code, and an idempotency key retained for the same user intent.
- Requires an explicit successful server response and persisted order ID before
  any payment or navigation state is shown.
- Binds quote-based order creation on the server to a live immutable quote
  snapshot, matching provider, native service, route codes, package facts,
  insurance/COD flags, and item value before persisting the trusted tariff.
- Initializes the payment session only after the order reference is returned;
  payment confirmation and subsequent short polling read server-owned status.
- Persists the pending order reference in session storage and rehydrates it
  through the authenticated order-detail endpoint after refresh.
- Unsupported aggregator COD is disabled in the UI and rejected in the payload
  builder because the current backend payment contract only supports the
  configured non-COD payment path. No order is created for that unsupported
  option.
