## Acceptance Criteria Source

The original checklist in `task-food-marketplace-parity-2026.md` requires:

- [x] Admin selects typed/registered route such as service home, promo detail, order history, support, etc.; no arbitrary code target.
- [x] Required route parameters validated before save.

- [x] External URL uses allowlisted HTTPS domain/scheme only.
- [x] Tester shows destination/fallback behavior for selected platform/app version.
- [x] Removing/deprecating a route identifies campaigns still referencing it.

## Scope Implemented

- Added a server-owned typed route registry with registered destinations for home, food service home, typed service home, promo detail, order history/detail, support and profile. Each entry includes parameter schema, supported surfaces, minimum app version, minimum manifest schema version, fallback route and lifecycle status.
- Added `POST /admin/experience/deep-links` typed route resolution. The server validates route ID, rejects unknown/deprecated routes, rejects unknown/missing/invalid parameters and returns the canonical allowlisted deep link. Existing first-party HTTPS external URL validation is exposed through the same protected endpoint.
- Added `GET /admin/experience/deep-link-registry` and an `include_usage=true` mode on the existing deep-link usage route. Usage records identify campaign manifest, revision, state, market, surface, app version and schema version.
- Added the Admin Deep Links page with a registry-backed picker, typed parameter fields, server validation, platform/app/schema tester, fallback explanation and first-party external URL validator. The page does not expose arbitrary code or scheme input.
- Added deprecation impact visibility: selecting a route shows matching live, draft, superseded and rolled-back campaign references before a route can be deprecated or removed from the registry.
- Preserved the existing manifest revision source of truth and draft handoff. Validation does not silently persist a campaign; the returned typed value enters the existing versioned draft/approval/publish/rollback lifecycle.
