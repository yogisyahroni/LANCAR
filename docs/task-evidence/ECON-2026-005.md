## Scope Implemented

- Extended the existing `courier_incentive_campaigns` control-plane table with market, zone, service, cohort, budget, policy version, reservation/reconciliation totals, and a configurable customer-pair fraud limit.
- Added server-owned progress and decision-event tables. A delivered order leg is counted only once per campaign/courier/order, so replaying a delivery transition cannot increment progress twice.
- Added an atomic database trigger that matches active campaigns by schedule and scope, snapshots the policy version, increments progress, reserves the reward from the campaign budget at target completion, and marks the progress `earned` or `budget_exhausted`.
- Added a reconciliation function and finance-admin-protected Admin endpoint. Reconciliation moves reserved liabilities to `reconciled` and updates the campaign total without creating a second payout source of truth.
- Added deterministic protections: courier role/profile validation, courier/customer and courier/merchant self-order rejection, repeated courier/customer pair cap, one event per order, and a maximum of two target deliveries per scheduled hour.
- Updated courier performance responses to read persisted campaign progress rather than counting all deliveries globally. The existing growth Admin page now exposes scope, budget, pair limit, and reservation/reconciliation values.
