## Scope Implemented

- Tambal Ban lifecycle is enforced server-side through the canonical roadside state path; courier shortcut transitions are rejected while unrelated service categories are unaffected.
- Completion report creation is restricted to the assigned roadside technician and requires an order state compatible with final proof before the first report is persisted.
- Duplicate completion submission for the same order is idempotent and resolves to the existing report instead of creating a second completion record.
- Backend validation requires configured before/after tire proof, structured condition-before/condition-after, bounded service duration, completion timestamp, and structured material codes.
- Courier flow persists inspection/proof draft state, calculates a bounded duration, and compiles against the current staging ancestry.
- Customer Android renders Tambal Ban lifecycle states as explicit human-readable stages and degrades unknown future states safely.
