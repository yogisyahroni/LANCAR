## Scope Implemented

- Completed the offer contract across persisted dispatch metadata, the mobile
  offers response, realtime `offer_created`, and FCM notification payloads.
  The contract includes dispatch identity, 90-second expiry, service code,
  route snapshot/provider/profile/distance/duration/ETA, payout and earning
  components, proof requirements, capability requirements, and policy version
  fields. Internal dispatch metadata is removed from the mobile response after
  the public fields are normalized.
- Added the canonical offer policy contract at
  `docs/contracts/courier-offer-lifecycle-2026.md`, including the lifecycle,
  atomic acceptance, idempotency, expiry, versioning, ranking weights, and
  fairness/no-permanent-lockout policy.
- Preserved the legacy `source: dispatch_engine_v1` metadata value for
  compatibility while adding explicit version fields for audit and experiment
  analysis. Normal and preferred dispatch paths use the same versioned offer
  and proof policy facts.
- Added a regression for expired acceptance: the dispatch is expired and
  rejected before the advisory acceptance lock or `order_legs` mutation can
  run. Existing route idempotency and courier transaction serialization
  contracts remain enforced.
