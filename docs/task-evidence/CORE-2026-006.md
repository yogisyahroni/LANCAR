## Scope Implemented

- Reused the existing `status_transition_policies` proof matrix and delivered-proof transactional guard; mandatory delivery completion already rejects missing proof before committing state.
- Added a server-owned one-time handoff token service. Tokens are generated with cryptographically secure random bytes, stored only as SHA-256 hashes, bound to order, actor, and pickup/delivery stage, expire after a bounded TTL, and enforce a maximum attempt count.
- Added replay, wrong-order, wrong-actor, wrong-stage, expiry, and attempt-limit handling in the PostgreSQL repository. Proof scan requests can carry a handoff token and the order service consumes it before the custody transition.
- Added authenticated issue and consume endpoints with role and courier-assignment checks, idempotency middleware, typed correlation-aware errors, and Android Retrofit request/model contracts.
- Existing transactional order transition code keeps proof rows append-only and prevents delivered state without a valid photo proof or existing persisted proof.
- Checked only locally proven criteria in the master task; the staging/migration runtime criterion remains unchecked.
