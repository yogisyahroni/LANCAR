# Evidence — A11Y-2026-005

## Scope Implemented

- Admin custom notifications use `role="status"`/`aria-live="polite"` for routine messages and `role="alert"`/`aria-live="assertive"` for error/critical messages.
- Critical notifications remain in page context until the operator explicitly dismisses them. Customer routine notifications expire after five seconds; Admin custom routine notifications remain for six seconds.
- Sonner fallback notifications preserve the same success/warning/error/critical severity instead of downgrading every event to informational.
- Operational controls expose distinct impact copy for `marketing_hide`, `new_order_gate`, `provider_gate` and `checkout_gate`; destructive confirmation includes action verb, target service and impact/recovery text.
- Notification actions include visible text, keyboard focus and explicit dismiss names; destructive order actions retain visible verbs and impact text.
- Shared loading/error/empty surfaces continue to expose status or alert semantics alongside the semantic color token.
- Customer Web preserves the server notification severity when projecting real-time events into the toast live region instead of coercing every event to informational.
