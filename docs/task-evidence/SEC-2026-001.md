## Scope Implemented

- Gateway and admin-service JWT validation pins `HS256` and the configured issuer; service-side bearer fallback no longer accepts an algorithm/issuer-confused token.
- Customer and courier order access remains identity/role-bound through gateway auth, admin-service session/role checks, and owner-scoped order queries. Order/proof/payment/refund/claim mutations consume the authenticated actor rather than client-supplied ownership.
- Trip-share tokens remain raw-token-to-SHA-256-hash only, are limited to the active order/courier join, expire at query time, and are rejected when `revoked_at` is set. Customer link creation revokes the previous customer-created link; an authenticated customer can explicitly revoke active links for their own order.
- Public tracking and handoff mutation/read routes now use the shared public Redis limiter. The limiter normalizes token-bearing paths so changing a token/id cannot create a fresh bucket for the same IP.
- Maps geocode/quote limits are wired in the API gateway and OTP send/verify limits are wired in auth-service. Public tracking, location-request submission, business API request submission, and trip-share reads are rate-limited in admin-service.
- Public maps configuration exposes only a browser-scoped key when applicable; server/provider secrets are kept in backend environment/configuration. Payment responses expose only the publishable client key and transaction token required by the payment SDK, never the server key.
