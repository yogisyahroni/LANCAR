# Evidence — ADMEXP-2026-019

## Acceptance Criteria Source

The original mandatory scenarios in `task-food-marketplace-parity-2026.md` were:

- `[x]` Marketing editor creates banner draft → preview → submits approval → publisher publishes → eligible app fetches revision → banner renders.
- `[x]` Reorder Home Layout through Admin → publish → app changes order without binary release.
- `[x]` Schedule campaign for future time → not visible before start → visible in correct timezone → disappears/expires correctly.
- `[x]` City-targeted campaign appears in matching city and not in non-matching city.
- `[x]` Old app version safely skips unsupported component while newer version renders it.
- `[x]` Invalid deep link/asset/schema blocks publish with field-level Admin error.
- `[x]` Unauthorized role cannot publish/rollback/kill-switch even by calling endpoint directly.
- `[x]` Two admins editing same draft produces explicit conflict rather than lost update.
- `[x]` Canary revision affects only assigned cohort/percentage.
- `[x]` Rollback from Admin restores last-known-good manifest and clients recover.
- `[x]` `new_order_gate` prevents new order entry but active order/tracking/support remains accessible.
- `[x]` Promo banner can be published while pricing backend still rejects user who is financially ineligible.

These are task-local requirements. Staging, provider-live, capacity-window and physical-device validation remain release follow-up under `GLOB-2026-014` and are not represented as ADMEXP-2026-019 acceptance criteria.

## Scope Implemented

- Added the backend `ADMEXP-2026-019` acceptance contract suite with 12 named tests covering resolver behavior, scheduling, targeting, app/schema compatibility, validation, authorization, optimistic conflict handling, canary rollout, rollback, `new_order_gate` recovery and promo/pricing boundaries.
- Added an Admin Chromium E2E flow that creates a draft, previews it, submits approval, approves it, re-previews after revision invalidation, publishes it, and verifies that a read-only operator cannot expose publish/rollback controls.
- Fixed the Admin editor save action to call the no-argument `onSave` callback instead of passing the browser click event as an `ExperienceForm`. This was the production-path defect found by the E2E flow.
- Reused the existing customer runtime E2E contract to prove revision changes render without a binary release and active-order recovery remains visible when experience content is unavailable.
