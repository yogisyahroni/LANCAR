## Scope Implemented

- Order-service push payloads now carry `service_code`, `service_sub_type`, `target`, `event_version`, and an order deep link whenever the persisted order snapshot provides the corresponding identity/timestamp.
- Customer FCM and WebSocket consumers share a device-local per-order event-version guard; an older numeric `event_version` is ignored and therefore cannot replace the current foreground notification or trigger a stale resync hint.
- Customer notification models and WebSocket parsing retain service, target, and version metadata for routing and diagnostics.
- `tembus://orders/{id}` now opens the customer order detail route. The detail ViewModel fetches the authoritative order snapshot on entry; tracking continues to fetch current order/tracking snapshots, so notification text is never treated as order truth.
- Deep-link validation now allowlists the supported `tembus://orders`, `tembus://booking`, and debug UAT shapes before extracting an order identifier.
