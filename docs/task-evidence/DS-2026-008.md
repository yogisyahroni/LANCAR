The original DS-2026-008 checklist in `task-food-marketplace-parity-2026.md` requires:

- [x] One visual system, different information priority per vertical.

- [x] Tambal/Towing active booking/service flow contains zero paid advertising.

## Scope Implemented

- Added `TembusServicePatterns.kt` as the shared non-Food identity/state family. `TembusServiceIdentityCard` uses the same TEMBUS card, typography, radius, button, and semantic badge roles while the identity data communicates the distinct service priority.
- Antar Barang now exposes a shared parcel identity in the booking flow and uses the shared calm TEMBUS app bar. Its existing route/package/quote/provider sequence remains the aggregator information hierarchy.
- Tambal Ban Home and Search now use the shared emergency identity, shared quote primitive, semantic theme roles, and the design-system empty state instead of the old gradient/emoji fallback.
- Tambal/Towing booking now uses shared technician, quote, safety, route, and re-quote primitives. Towing safety, vehicle/dropoff, route, and consent remain ahead of order submission.
- `CourierPriceCard` continues to adapt authoritative provider responses into `TembusCarrierRateData`; the model and renderer accept no sponsored, campaign, or paid-ranking input.
- Added `validate-service-pattern-surfaces.mjs` to scan Tambal/Towing active-flow and Aggregator carrier-comparison source surfaces for paid-inventory identifiers.
