## Scope Implemented

**Item-level unavailable + substitution propose/approve flow** — NEW untuk FOOD-2026-007:
1. **ReportFoodItemUnavailable** — merchant laporkan item stok habis saat `preparing`. Validasi zero-trust: merchant harus owner order + item ada di order + quantity valid. Di-record ke `food_item_unavailable` table.
2. **ProposeFoodSubstitution** — merchant usulkan item pengganti. Validasi: order preparing, tidak ada duplicate proposal pending untuk item yang sama, replacement item valid milik merchant. Price delta (`replacement_price - original_price`) dihitung server-side (snapshot `food_order_items.item_price` vs live `merchant_menu_items.harga`) — client tidak bisa manipulasi harga. Proposal disimpan + notif push ke customer.
3. **GetPendingSubstitutionProposals** — customer lihat proposal pending (authorization: hanya owner order).
4. **DecideFoodSubstitution** — customer approve/reject. Guard: hanya saat order `preparing`/`searching` (belum assigned courier), proposal masih `pending`, idempotent via WHERE guard. Jika approve → update `food_order_items.item_price` ke harga replacement + event publish. Jika reject → notif ke merchant.

State guard kritis: tidak ada stok/transisi order yang berubah — item unavailable hanya mencatat, tidak membatalkan order. Substitution approval update harga item (akan ter-reflect di next price recalculate / payment gateway).
