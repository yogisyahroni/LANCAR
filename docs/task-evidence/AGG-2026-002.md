# Evidence — AGG-2026-002

## Scope Implemented

- Browser customer order, aggregator, and payment-link flows use the LANCAR
  maps API; no browser-side Nominatim/TomTom geocode call remains.
- Geocode and reverse-geocode responses expose independent
  `display_label`, `address_line`, `city`, `district`, `postal_code`,
  `country_code`, and provider place metadata while retaining legacy `label`.
- Provider location codes are derived only from server-side
  `maps_provider_config.location_mappings`; absent mapping data produces an
  empty mapping rather than a guessed carrier code.
- Mapping version participates in Redis cache keys. Mapping match version and
  count are included in structured maps observations for audit/operations.
- Address picker propagates the normalized city into the order form; the
  aggregator reverse-geocode path uses the normalized display label and city.
