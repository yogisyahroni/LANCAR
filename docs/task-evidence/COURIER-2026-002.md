## Scope Implemented

- Extended the existing `courier_documents` source of truth with document
  status, verification source, number, issue/expiry/revocation metadata,
  storage provider/key/access class, checksum/MIME metadata, retention, and
  logical deletion fields. Existing `is_verified` remains a compatibility
  projection synchronized by a database trigger.
- Added `courier_vehicles` review normalization for make, model, type/category,
  plate, production year, engine CC, and maximum weight capacity, while keeping
  the structured vehicle table authoritative and projecting compatible legacy
  profile fields.
- Added the server-side `courier_profile_documents_eligible(profile_id)` policy
  function. Expiry, revocation, and retention-expiry suspend an ACTIVE courier
  through a database trigger; activation, matching, relay, SOS, idle tracking,
  surge supply, broadcast online targets, duty toggle, retention, and analytics
  paths use the policy rather than a client-controlled toggle.
- Added restricted admin document reads and verification/rejection/revocation
  actions with role/TOTP gates and `courier_document_access_log` audit records.
  Local sensitive files use a private scoped storage path and an owner-or-
  compliance-admin authorization check in auth-service before serving.
- Added the hourly compliance worker. It expires documents, enforces retention
  deletion, removes local retained files through the safe path resolver, and
  creates idempotent 30-day, 7-day, and day-of reminders through the existing
  Communication `createNotification` platform. Failed notifications remain
  retryable.
