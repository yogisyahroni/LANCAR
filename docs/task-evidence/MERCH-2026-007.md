# Evidence — MERCH-2026-007

## Acceptance Criteria Source

Original checklist from `task-food-marketplace-parity-2026.md`:

- `[x]` Merchant UI has separate `Promo` and `Iklan` products.
- `[x]` Promo changes financial offer; Ads purchases eligible visibility; organic ranking remains independent.
- `[x]` Ads creative cannot fake discount/ETA/rating.
- `[x]` Merchant sees attributable paid vs organic performance separately.

## Scope Implemented

- Added explicit `product_type` and merchant ownership to the existing
  `promo_campaigns` registry. Existing food-discovery sponsored rows are
  backfilled as Ads and checkout/admin promo queries now accept only
  `product_type = 'promo'`.
- Added merchant-owned Ads purchase records with idempotency, ownership,
  prepaid balance check, append-only `ads_spend` statement entry, audit event,
  and transactional replay behavior. Existing `merchant_promos` and merchant
  settlement discount calculation remain the financial-offer path.
- Added server-side creative policy for headline/body, rejecting discount,
  ETA, and rating claims; the database boundary repeats the zero-discount and
  prohibited-claim checks.
- Added merchant Ads list/create/active/performance endpoints. Paid events and
  spend are joined only to owned Ads; organic delivered food orders/revenue are
  reported separately and exclude attributed Ads orders.
- Added native merchant navigation and `Iklan` screen beside the existing
  `Promo` entry point. The screen contains no discount/ETA/rating controls and
  displays authoritative campaign status, spend, attribution, and discovery
  metrics from the merchant API.
- Kept organic ranking independent of commission or Ads budget. Sponsored
  placement and event attribution require `product_type = 'ads'`.
