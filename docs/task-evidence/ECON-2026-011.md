# Evidence — ECON-2026-011

## Acceptance Criteria Source

Original checklist from `task-food-marketplace-parity-2026.md`:

- `[x]` Unit economics computed from ledger truth, not analytics guess.
- `[x]` Contribution metrics by market/service/order cohort have consistent definition.
- `[x]` Negative-margin/outlier orders trace back to exact policy/version/components.
- `[x]` Finance and Product use same financial definitions.

Required decomposition:

`customer paid → tax/provider fee/promo subsidy → merchant payable → courier payable → carrier payable → Ads/other charges → platform contribution`

## Scope Implemented

- Replaced the old analytics-only `unit-economics` implementation that referenced legacy aggregate fields with a server-side order-facts query sourced from persisted payments, refunds, order/pricing snapshots, courier earnings ledger, merchant settlements, provider invoice items, promo redemptions, and attributed double-entry ledger expenses.
- Added one versioned Finance/Product contract in `docs/contracts/unit-economics-2026.md`. The same dimensions (`market`, canonical `service`, and day/week/month `order_cohort`) and formula are returned for summary, cohort, and outlier views.
- Added explicit source coverage and reconciliation status. Missing payment facts are surfaced as `incomplete`; they are never silently converted into a healthy contribution result. Late settlement/invoice/ledger facts are attributed by `order_id` across history while the order financial timestamp controls cohort inclusion.
- Added negative contribution drilldown with order, market/service cohort, all financial components, source for each payable, pricing rule/policy version, merchant contract version, and exact pricing components.
- Updated the Admin Finance panel to show the shared definition, coverage state, cohort contribution table, and negative-margin outlier table while retaining the existing endpoint and dashboard query path.
