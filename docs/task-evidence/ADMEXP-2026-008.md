# Evidence — ADMEXP-2026-008

## Acceptance Criteria Source

The original checklist in `task-food-marketplace-parity-2026.md` requires:

- [x] Active orders, tracking, proof, support and refund/recovery entry remain reachable when discovery/new-order entry is disabled.
- [x] Admin UI explains blast radius before execution and requires reason.
- [x] High-impact kill switch supports expiry/auto-revert or explicit review time where useful.
- [x] Business backend still validates service/provider availability; hiding UI is not the sole enforcement.
- [x] Kill-switch action emits high-severity audit/notification to appropriate ops channel/dashboard.

## Scope Implemented

- Added ordered, typed `service_entries` to the existing `service_grid` manifest schema and Admin editor. Each entry supports service/category, discovery enabled state, position, presentation label/subtitle/badge and bounded fallback behavior while leaving transaction truth with domain services.
- Added a dedicated Kill Switches Admin page and confirmation modal. The UI distinguishes `marketing_hide`, `new_order_gate`, `provider_gate` and `checkout_gate`, explains blast radius, requires a reason and rollback plan, exposes expiry/review time and active-order preservation, and uses the existing App Experience permissions.
- Added typed service-control API endpoints backed by the canonical `feature_flags` store. High-impact controls require `super_admin` or `ops_security`, TOTP and idempotency; writes are transactional, immutable changes are recorded in `feature_flag_logs`, Redis caches are invalidated, and existing email/Slack alert paths are invoked.
- Added order-service enforcement for `new_order_gate` at both regular order creation and food order creation. The reader matches service, market, city/zone and schedule/expiry, fails closed on control-plane read errors, and does not consult `marketing_hide`, so active-order read/recovery paths are not blocked by discovery controls.
- Updated the native customer renderer to respect ordered/disabled service entries and presentation overrides only after intersecting with the authoritative enabled-service response.
- Documented the semantic contract and kept operational controls out of generic public feature-flag resolution.
