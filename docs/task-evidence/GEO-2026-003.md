## Scope Implemented

- Geocode search returns bounded candidate lists from TomTom or the configured OpenStreetMap fallback; the web `AddressPicker` displays candidates and applies a location only after the user selects one.
- Reverse geocode preserves the requested pin coordinates while changing only the returned display label/address components.
- Normalization now carries address line, city, district, postal code, country code, provider place ID, and server-controlled provider location mappings/version/count.
- Redis geocode/reverse-geocode keys are provider/scope/query or coordinate scoped, mapping-version aware where mappings are applied, and use a bounded configurable TTL.
- Results expose provider and confidence; provider observations record source, result count, latency, cache hits, fallback, and failure state.
- Provider keys remain server-side and provider failure returns an empty candidate list/null result rather than invented location data.
