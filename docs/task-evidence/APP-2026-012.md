## Scope Implemented

- Added experience observability aggregation over the existing canonical `event_outbox`, including manifest fetch, cache, parse/schema fallback, render, asset, deeplink, startup and network reliability signals, with p95 latency and dimensions for manifest revision, market and app version.
- Kept campaign impression/click/dismiss counts separate from reliability guardrails so marketing activity cannot dilute failure thresholds.
- Added Android instrumentation across manifest fetch/cache/validation, dynamic section rendering, broken assets, deeplinks, campaign dismissal, startup latency and Crashlytics release context.
- Added admin observability and guardrail endpoints. A one-hour reliability threshold evaluates a minimum sample and failure-rate guardrail, automatically invoking the existing manifest rollback ownership when approval is already present and otherwise returning a manual rollback recommendation.
- Added dashboard breakdowns and reliability-versus-marketing presentation, frontend client logging, canonical event header support for app version, and indexes for the existing outbox access patterns.
