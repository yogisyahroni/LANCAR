## Acceptance Criteria Source

- [x] Safe GET/snapshot caching separated from mutation queue.
- [x] Mutation retry only for idempotent/safe operations.

## Scope Implemented

Release clients use the same bounded OkHttp timeout/retry/cancellation contract: safe GET/HEAD reads may retry once, cancelled calls never retry, and HTTP mutations are never transparently retried. Snapshot refresh is separate from courier mutation replay, while merchant offline data is read-only. The customer experience asset worker requires `UNMETERED` network and exponential backoff, so campaign/media prefetch is reduced on metered data. Customer and merchant authenticated shells now observe validated connectivity, render explicit offline and five-second pending-request recovery states, and retry by reloading the owning data source; courier already exposes stale/offline data recovery in its order shell.
