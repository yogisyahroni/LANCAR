## Scope Implemented

- The customer web order flow persists an order before payment using a stable idempotency key, stores a pending transaction fingerprint in session storage, recovers a persisted order after refresh, and reuses a payment idempotency key for retries.
- Quote calculation is server-backed from verified pickup/dropoff coordinates, package facts, selected service, insurance, and promo state; the form does not invent price or route data.
- Payment confirmation remains server-owned: the modal checks payment status and polls the server after gateway callbacks instead of marking success locally.
- Address picker uses saved/manual/pinned coordinates and cancels stale geocode requests. Order history/detail/tracking use the same existing API state contract and responsive portal layout.
