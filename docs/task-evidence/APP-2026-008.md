## Scope Implemented

- Extended the existing experience manifest control plane with governed targeting dimensions for market, city, zone, locale, service-usage cohort, new/existing user, role, cohort, experiment reference and explicit assignment. Strict schema validation rejects unknown/sensitive attributes and preserves the existing protected-property boundary.
- Added server-side audience resolution and specificity ranking. User `new`/`existing` status is derived from the server-owned `users.created_at` record when needed; role is taken only from authenticated gateway identity. The public response contains the resolved presentation manifest and never exposes targeting rules or admin fields.
- Added IANA schedule timezone validation and conversion of timezone-less authoring wall-clock values to UTC `TIMESTAMPTZ` instants. Explicit-offset timestamps remain respected, and nonexistent DST wall-clock values are rejected.
- Added admin draft audience simulation for market, locale, app version, cohort, experiment, assignment, city/zone, service usage, user status, role and schedule. The simulation returns only matched/reason/context/selected revision data.
- Added an atomic publish guard requiring an active untargeted fallback before a targeted manifest can replace the last fallback. Public cache `Vary` now covers every audience header plus authorization.
- Added the schedule timezone migration and updated the app experience contract documentation.
