## Acceptance Criteria Source

## Scope Implemented

- Backend capability matching uses the vehicle/service matrix and fail-closed behavior for unknown combinations.
- Backend dispatch filtering preserves capability, availability-state, radius, freshness, and workload guards before assignment.
- Customer Android refreshes nearby candidates after the pickup location changes, invalidates a stale preferred selection, and refuses create when a preferred roadside courier is not freshly verified as available or conditional.
- Discovery expands only across ordered radius stages stored in `delivery_service_products.search_radii_km`; roadside defaults are seeded as tambal ban 1/5/10 km and towing 10/25/50 km.
- Customer discovery shows a live radar pulse, refreshes every 10 seconds, exposes server `last_updated_at`, and lets the customer sort candidates by nearest, cheapest, fastest, or rating.
- Admin delivery-service settings validate and persist ordered radius stages; malformed roadside stages and values above 50 km are rejected.
- A selected tambal ban/towing technician is never silently replaced by the normal queue if it becomes unavailable during order creation; the order becomes `no_courier_found` with a retryable event.
