# Evidence — APP-2026-005

## Acceptance Criteria Source

Original checklist from `task-food-marketplace-parity-2026.md`:

- Banner image/copy/badge/CTA/deep-link can change remotely.
- Internal destination uses allowlisted typed route, not arbitrary string execution.
- External URL uses explicit domain allowlist and safe browser handoff.
- Promo banner eligibility is presentation-only; final promo/discount is validated by promo/pricing backend.
- Banner supports impression/click analytics with manifest revision + campaign id.
- Broken target cannot trap/crash user; fallback action is no-op or safe landing page.

## Scope Implemented

- Extended the existing experience manifest contract for remotely managed banner/promo campaign identity, copy, badge, verified asset reference and exactly one CTA target.
- Added native `DynamicHeaderBanner` and `DynamicPromoCard` Compose components. Images resolve only through the existing checksum-verified local asset cache; missing/decode-failed images use a native fallback.
- Added `RemoteDeepLinkResolver` with a finite compiled internal destination enum and exact first-party HTTPS host allowlist. Both resolver output and the external browser handoff are validated; invalid targets become a no-op/failure telemetry path.
- Wired the dashboard and root navigation to typed remote targets. No manifest string is passed to `NavController.navigate` or an unvalidated implicit intent.
- Kept promo content presentation-only. The manifest schema rejects pricing/discount/eligibility fields, while the existing customer promo/pricing endpoints remain authoritative for eligibility and final discount validation.
- Added authenticated banner impression/click telemetry through the existing canonical `event_outbox`, carrying manifest revision, campaign/section identifiers, correlation metadata and a pseudonymous actor identifier. Analytics failures are best-effort and cannot block the dashboard.
