# Evidence — A11Y-2026-002

## Scope Implemented

- Customer and Admin login inputs now expose explicit labels, `aria-invalid`/`aria-describedby` field errors and persistent alert semantics.
- Dispute, Aggregator and On-Demand forms connect validation messaging to the affected controls instead of relying on a red border alone.
- The On-Demand browser fixture covers pickup, dropoff, recipient name, recipient phone and package category validation; each invalid control points to the rendered matching error text.
- Customer order/payment status surfaces use readable labels and supplemental icons; status color is no longer the only differentiator.
- Customer desktop and mobile navigation expose the current route with `aria-current="page"`; the active route is therefore not conveyed by color alone to assistive technology.
- Admin notification/toast actions use visible text/icon meaning, severity-aware live-region semantics and keyboard-operable buttons; collapsed sidebar items expose their names through `aria-label`/`title`.
- Audited service, order, chart and map surfaces retain readable labels/summaries alongside semantic color tokens.
