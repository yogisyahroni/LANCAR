# Evidence — APP-2026-006

## Acceptance Criteria Source

Original checklist from `task-food-marketplace-parity-2026.md`:

- Core brand/accessibility tokens have safe packaged defaults.
- Remote values are constrained by enum/range/contrast validation, not arbitrary styling instructions.
- Critical transaction screens may opt out of campaign theming.
- Unsupported theme token falls back safely.
- Do not remotely download executable UI code or arbitrary font binaries.

## Scope Implemented

- Added the `design_tokens` manifest section to the existing admin-service schema with strict semantic presets for accent, background, corner, spacing and badge presentation. Unknown keys, arbitrary colors, unsupported enum values and remote font instructions are rejected before publication. Fixed server palette pairs are checked for WCAG AA contrast of at least 4.5:1.
- Added `RuntimeDesignTokens` with packaged brand/accessibility defaults, bounded Dp mappings, fixed light/dark palette mappings and a client contrast guard. Unsupported or missing values fall back per token, and a failed future palette guard falls back to the packaged default object.
- Added `RuntimeThemeProvider` and kept it out of the global `TEMBUSCustomerTheme`. `DynamicHomeRenderer` exposes `allowRuntimeTheme`, so critical transaction surfaces can explicitly use packaged defaults. Dashboard campaign banners and promo cards consume only the compiled provider values.
- Marked `design_tokens` as non-home manifest metadata so it cannot become an arbitrary renderer instruction. No WebView, JavaScript, executable UI code, arbitrary CSS, arbitrary font family, or remote font binary path was added.
- Reused the existing checksum/canonical `sections` JSON payload; no table or migration was introduced.
