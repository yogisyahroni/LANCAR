## Scope Implemented

- Added canonical `Money` with integer minor units, ISO-4217 normalization, currency exponent validation, decimal/rational half-up arithmetic, overflow checks, and compatibility conversion for legacy IDR fields. Financial calculations in the order-service pricing, payment, refund, payout, settlement, voucher, insurance, and promo paths now use this model rather than binary floating-point arithmetic.
- Added canonical currency/minor-unit fields to pricing estimates, orders, payments, refunds, payouts, ledger journals/entries, and relevant client DTOs. Existing IDR columns remain compatibility projections and are never populated with non-IDR values.
- Added FX conversion request/record and repository persistence with source/target amounts, source/target currencies and exponents, rate text, rate source, observed time, spread, fee, and locked-rate reference. The FX service rejects missing metadata and persists the immutable conversion record.
- Added jurisdiction-aware tax snapshots with currency, minor unit, DPP/PPN minor amounts, tax jurisdiction, effective time, and a version derived from the tax rule. Tax inputs must share one currency.
- Added ledger and reconciliation invariants that reject mixed currencies and mismatched exponents before persistence. PostgreSQL ledger constraints and the deferred balance trigger validate canonical minor-unit columns; legacy IDR rows are backfilled safely.
- Wired server-side client formatting: the web order summary uses `Intl.NumberFormat` with server currency/exponent, and Android uses `BigDecimal`/`Currency` formatting for canonical amounts. Existing `formatRupiah` is retained only as an IDR compatibility helper.
- Existing IDR-only gateways/configuration fail closed for non-IDR instead of reinterpreting a foreign amount as rupiah.
