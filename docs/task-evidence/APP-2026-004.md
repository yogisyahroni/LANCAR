# Evidence — APP-2026-004

## Acceptance Criteria Source

Original checklist from `task-food-marketplace-parity-2026.md`:

- Native OS splash remains minimal/static/local for reliable startup.
- Optional campaign intro can use remotely managed image/animation asset and localized copy from cached manifest.
- Network fetch does not block first usable app screen; show campaign only when config+asset are already valid/cached or quickly available by policy.
- Campaign supports start/end time, market, locale, cohort, min app version, frequency cap, max impressions and dismiss/skip policy.
- Missing/expired/corrupt asset skips campaign and proceeds normally.
- Campaign can be remotely killed instantly.
- Next-campaign assets can be prefetched so a new promo can appear on subsequent launch without app update.

## Scope Implemented

- Preserved the existing Android Core SplashScreen setup with local application/activity themes, local splash background/icon resources and no remote startup dependency.
- Added `campaign_intro` to the existing presentation-only experience-manifest contract. Its localized title/body, optional image/animation asset, enable/kill flag, impression cap and dismiss/skip policy are validated before rendering.
- Added `StartupCampaignPolicy` to revalidate the cached manifest's schedule, market, locale, app version and targeting scope, then enforce frequency cap, maximum impressions, dismissal and missing/corrupt asset behavior without network access.
- Added checksum-verified local asset resolution. Remote assets are prefetched into an isolated bundle during APP-2026-002 background refresh; installed `/assets/` resources are verified in place. A failed/partial asset stage cannot replace LKG.
- Added atomic local `StartupCampaignStore` for per-account campaign impressions and dismiss state. Account changes clear delivery state and the experience manager resets to a packaged scope before loading the new audience.
- Added a non-blocking coordinator and native Compose campaign layer after the dashboard shell is ready. The UI consumes only verified local paths, handles image decode errors by skipping, and never receives a remote URL.
- The existing manager snapshot flow removes a campaign when a newer disabled/expired/changed manifest arrives, providing the remote kill path without an app binary update.
