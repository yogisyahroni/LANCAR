# Evidence — GLOB-2026-011

## Acceptance Criteria Source

Original checklist from `task-food-marketplace-parity-2026.md`:

- `[ ]` External clients use scoped credentials/OAuth-equivalent, not internal API keys.
- `[ ]` Public API versioning/backward compatibility policy documented.
- `[ ]` Quote/create/get/cancel/track operations use idempotency and ownership scopes.
- `[ ]` Webhooks are signed, replay-protected, retryable and have delivery logs.
- `[ ]` Sandbox/test environment uses non-financial/provider-safe behavior.
- `[ ]` Rate limits/quotas and abuse controls per client.
- `[ ]` Developer API cannot bypass normal pricing/payment/risk/state invariants.

## Scope Implemented

- Added the developer-platform service with scoped, bcrypt-backed sandbox/live credentials, client/environment validation, expiry checks and per-client quota enforcement. Internal provisioning remains protected by the internal service credential and is not exposed as the public client credential model.
- Added versioned `/api/v1/developer/v1/` routing plus OpenAPI, versioning, idempotency, webhook and sandbox documentation. The compatibility policy requires additive changes in v1 and a separately introduced major version for breaking changes.
- Added owner-scoped quote, order create/get/cancel and tracking proxy paths. Mutations require an idempotency key, persist request hashes and replay responses safely; live mutations call the canonical order service with a short-lived owner JWT and preserve server-authoritative pricing, payment, risk and state transitions.
- Added encrypted webhook subscription secrets, exact-body HMAC signatures with timestamps, replay protection, HTTPS/private-network URL validation, delivery attempt logs, bounded retries and dead-letter state.
- Added provider-free sandbox quote/order behavior with zero financial obligation and a dedicated sandbox order store; sandbox operations never call payment or external providers.
- Added gateway auth matrix/proxy wiring, per-client rate limiting and abuse-safe request validation. Webhook payloads are sanitized and secrets, credentials and sensitive fields are not returned.
