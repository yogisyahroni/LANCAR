# Evidence — APP-2026-010

## Acceptance Criteria Source

Original checklist from `task-food-marketplace-parity-2026.md`:

- `[x]` Remote image/animation assets use HTTPS CDN/object storage; app never needs secret bucket credential.
- `[x]` Manifest records content type, dimensions/aspect expectation, size limit, checksum/version and expiry/cache policy.
- `[x]` Client validates content type/size and uses disk cache with bounded eviction.
- `[x]` Prefetch only eligible upcoming assets; do not waste bandwidth downloading every campaign globally.
- `[x]` Deleted/rolled-back campaign does not break old cached manifest; asset lifecycle respects manifest retention window.
- `[x]` Low-bandwidth/data-saver fallback uses lighter asset or no campaign.

These are the original APP-2026-010 requirements. Staging deployment and interactive device validation are release follow-ups because they are not additional checklist requirements in this TASK-ID.

## Scope Implemented

- Extended the existing admin-service manifest asset schema and CMS picker with MIME type, dimensions/aspect ratio, byte limit, immutable version, expiry, cache policy, retention deadline and optional lighter fallback metadata. New revisions normalize complete metadata while old JSONB rows remain readable.
- Preserved the HTTPS/no-user-info asset boundary; the customer app downloads directly from the declared URL and never receives bucket credentials.
- Reworked customer Android staging to stream into an isolated temporary bundle, verify response MIME type, declared/global size limits, SHA-256 and declared image dimensions/aspect ratio, then atomically commit. Failures log only manifest/revision/error class and leave the LKG envelope untouched.
- Added a bounded cache cleanup policy with active LKG protection, per-bundle retention markers, 30-day default retention and stale staging cleanup. A superseded or rolled-back revision can continue using its retained bundle when it is the cached LKG.
- Added a 24-hour eligibility policy that selects only referenced assets plus their declared fallbacks. A Wi-Fi constrained WorkManager job refreshes the audience-scoped manifest; it does not enumerate or download a global campaign registry.
- Added metered/data-saver detection. The app selects a declared lighter fallback and otherwise omits the affected asset/campaign rather than downloading the heavy primary asset.
- Added pure delivery/prefetch policy tests and documented the publishing/lifecycle runbook.
