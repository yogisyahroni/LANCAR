# Evidence — TOW-2026-005

## Scope Implemented

- The courier proof upload endpoint checks the assigned `order_legs` status before accepting `vehicle_photo_before`. Once the leg is `in_transit` or downstream (`arrived_dropoff`, `unloading`, `completed`, `delivered`, `cancelled`, or `failed`), the endpoint returns `ERR_PROOF_IMMUTABLE` and does not save the upload.
- Normal and preferred dispatch now persist the selected approved `courier_vehicles.id` in offer metadata. Offer acceptance verifies that vehicle still belongs to the authenticated courier and writes it to `order_legs.vehicle_id`.
- Towing proof uploads include the bound vehicle in their audit payload, and the towing report repository resolves the vehicle from the authenticated courier's order leg instead of trusting a client-provided vehicle identity. A report cannot be created without that binding.
- The claim repository requires `towing_reports.vehicle_id = order_legs.vehicle_id`, the same operator on the assigned leg, and a unique claim per report. This prevents cross-order, cross-operator, and cross-vehicle claim creation.
- Admin claim decisions require an allowed reviewer role, a liability decision, a positive approved amount (or an explicit rejection), and a reason. The repository stores reviewer/timestamp and writes `towing.damage_claim.liability_decided` to `audit_logs`.
- Compensation can be reconciled only once after approval. The channel (`settlement`, `insurance`, or `platform_reserve`) and non-empty reference are required; the claim transitions to `paid` and writes `towing.damage_claim.compensation_reconciled`.
