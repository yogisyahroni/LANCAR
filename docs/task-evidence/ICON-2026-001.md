# Evidence — ICON-2026-001

## Acceptance Criteria Source

- Use Lucide as the default functional icon family.
- Do not mix Lucide with emoji, filled Material icons or an undocumented second icon package.
- Functional icon meaning must remain accompanied by visible text where ambiguity is possible.

## Scope Implemented

- Added a source guard rejecting non-approved icon package imports and pictographic emoji in application source, while requiring `aria-hidden` or explicit accessible semantics for direct Lucide, dynamic icon and raw SVG render sites.
- Extended the guard to reject a button whose complete direct content is a single decorative icon when it has no `aria-label` or `title`; conditional icon-only controls and visible-text controls remain covered by the rendered route inventory.
- Replaced emoji functional controls in Customer order creation, order mode selectors, payment/template actions and vehicle recommendations with Lucide icons or text labels.
- Named the remaining audited Customer/Admin icon-only controls (row actions, pagination, modal close, attachment/send, API-key/config switches and table controls) with contextual labels/titles and explicit button types.
- Extended the icon-only guard to require a matching native `title` tooltip when a direct icon-only button already has an accessible name, then filled the remaining detected Customer/Admin close, navigation, filter, pagination, map and editor actions without changing their handlers.
- Preserved the documented brand/carrier/map/data-visualization rendering-boundary exceptions.
