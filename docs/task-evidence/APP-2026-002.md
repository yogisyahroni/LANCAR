# Evidence — APP-2026-002

## Acceptance Criteria Source

Original checklist from `task-food-marketplace-parity-2026.md`:

- App starts from packaged defaults or last-known-good config; startup never waits indefinitely for network config.
- Refresh config asynchronously using ETag/revision/TTL.
- Cache is atomic: partially downloaded manifest/assets never replace last-known-good revision.
- Unsupported schema/component/property is ignored or falls back safely, never crashes home.
- Config is scoped by market/locale/app version/surface.
- Logout/account switch clears user-targeted assignment data that must not leak between accounts.

## Scope Implemented

- Added a customer Android experience-manifest model and strict sanitizer with schema, component/property, deep-link, asset, schedule, app-version and scope validation.
- Added a Retrofit API adapter for the existing `APP-2026-001` public resolver, including `If-None-Match`, `ETag`, HTTP 304 and response failure handling.
- Added a DataStore-backed LKG envelope containing manifest JSON, scope, revision, ETag, timestamp and asset bundle identity.
- Added background startup coordination: the packaged safe default is exposed immediately, while disk/network refresh runs in a supervisor scope and is bounded by a 10-second timeout.
- Added TTL short-circuiting, ETag refresh, validation-before-publish and atomic remote-asset staging. Assets are downloaded into an isolated directory, checksum-verified, renamed atomically and committed before the manifest envelope is written.
- Added account-targeted assignment persistence with identity matching and explicit logout/account-switch clearing.
- Kept actual order/payment/state-machine truth outside the remote presentation-config boundary.
