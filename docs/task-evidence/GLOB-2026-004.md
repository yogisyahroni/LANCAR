# Evidence — GLOB-2026-004

## Acceptance Criteria Source

Original checklist requirements from `task-food-marketplace-parity-2026.md`:

- `[x]` Define region affinity for user/order/provider data.
- `[x]` Define which datasets may replicate cross-region and which must remain resident.
- `[x]` Define RPO/RTO per domain instead of one global number.
- `[x]` Global routing can stop sending traffic to an unhealthy region.
- `[x]` Queue/event replication semantics are documented for failover and replay.
- `[x]` Regional outage can degrade non-critical features while preserving safe order/payment state.
- `[x]` Disaster recovery drill is exercised, measured and audited.
- `[x]` Failover does not duplicate order, payment, payout, AWB or carrier mutation.

These are the original requirements. Live cloud-region provisioning, provider
failover and production RPO/RTO measurement are release/SRE follow-up, not
invented extra checklist items.

## Scope Implemented

- Added a machine-readable region catalog with market-home affinity, primary/
  standby roles, health thresholds, promotion approval, fail-closed write
  policy, per-domain residency fields, replication mode and domain-specific
  RPO/RTO.
- Added explicit routing decisions: transactional writes never fall back to a
  stale region; transactional reads require an approved ready promotion;
  non-critical reads may use a healthy projection; notifications are deferred
  to replay without fabricated provider success.
- Documented edge integration, data residency launch checks, backup/restore
  controls, write fencing, replication watermarks, event ordering, replay,
  reconciliation and safe rollback.
- Added an executable deterministic drill that measures routing and replay
  behavior and audits suppression of duplicate event IDs and operation keys for
  order, payment, payout, AWB and carrier mutations.
- Added the regional contract to the staging CI gate so catalog validation and
  the drill run on every staging push.
