## Acceptance Criteria Source

Original checklist from `task-food-marketplace-parity-2026.md`:

- `[x]` Manifest has strict schema and maximum payload/component/asset limits.

- `[x]` Arbitrary WebView HTML is not allowed for core order/payment/identity flows.
- `[x]` Deep links and external domains are allowlisted.
- `[x]` Server sanitizes user-visible remote text/URLs and prevents unsafe schemes.
- `[x]` Compromised CMS account blast radius is limited by role/approval/audit/kill switch.

These are the original APP-2026-011 requirements. Staging deployment and interactive device validation are release follow-ups because they are not additional checklist requirements in this TASK-ID.

## Scope Implemented

- Added server-side aggregate and per-component UTF-8 byte limits to the existing strict Zod manifest contract, while retaining bounded section and asset counts and existing protected-key/schema validation.
- Preserved the existing SHA-256 canonical payload checksum and optional HMAC signature strategy, and bound Android response/cache acceptance to quoted ETag/checksum equality and matching manifest revision.
- Expanded server and Android protected-key handling to reject HTML, JavaScript, shell/command, SQL/reflection and bytecode-shaped remote properties. The experience renderer continues to use native allowlisted components and does not render manifest HTML in core flows.
- Kept deep links and external URLs constrained to the existing allowlists; server and Android text/URL sanitizers reject markup and unsafe schemes.
- Added an audited, idempotent published-manifest kill switch with database constraint/index, role + TOTP + idempotency-key protected admin routes, and dashboard emergency disable/restore controls. Resolver and publish fallback exclude kill-switched revisions.
- Added the public gateway route policy and dedicated rate limiter for the presentation-only manifest endpoint.
