# Evidence — DS-2026-004

## Acceptance Criteria Source

The original DS-2026-004 checklist in `task-food-marketplace-parity-2026.md` requires:

- [x] Organic `MerchantCard` and Sponsored variant share content anatomy; Sponsored always adds disclosure that merchant creative cannot disable.
- [x] Rating, distance, ETA, open/closed, halal, and delivery fee come from authoritative/source-defined data, not ad payload.
- [x] Promo discount badge does not mean sponsored, and Sponsored label does not mean a merchant discount.
- [x] Image aspect, text truncation, fallback image, favorite button, and accessibility semantics are standardized.

## Scope Implemented

- Added the canonical Customer Android `TembusCommerce.kt` family with merchant, sponsored merchant, menu item, promo, rating, ETA/distance, price, voucher, cart-bar, and sponsored-label primitives.
- Added the equivalent Customer Web `TembusCommerce.tsx` family using the existing TEMBUS core primitives and semantic token classes.
- Refactored Food Home's local merchant card to map `FoodMerchant` through `toTembusMerchantCardModel` and select the organic or mandatory-disclosure sponsored wrapper from the server `is_sponsored` flag.
- Kept ad copy out of the card model: the existing `adLabel` cannot replace or suppress the fixed `Sponsored` disclosure. Existing campaign impression/click recording remains in `FoodViewModel`.
- Kept factual fields separate from advertising: rating, distance, open/closed, halal, and media are mapped from `FoodMerchant`; ETA and delivery fee render only when a future authoritative quote supplies them and are never client-estimated.
- Standardized 4:3 media, neutral deterministic fallback, bounded text, 48dp/48px favorite control, accessible names/pressed state, and independent promo badge semantics.
