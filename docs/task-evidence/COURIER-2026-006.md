# Evidence — COURIER-2026-006

## Acceptance Criteria Source

Original requirements from `task-food-marketplace-parity-2026.md`:

- `[ ] Per-job earning breakdown immutable after settlement except compensating adjustment.`
- `[ ] Wallet available/pending/held/withdrawn states explicit.`
- `[ ] Payout/disbursement idempotent.`
- `[ ] Statement shows order/incentive/adjustment/tax/fee separately.`
- `[ ] Courier cannot withdraw promotional/non-withdrawable balance accidentally.`

## Scope Implemented

- Added settlement timestamps and a database guard that prevents mutation of settled earning facts, while directing corrections to append-only compensating adjustment entries.
- Added server-side withdrawability normalization: promotional/non-withdrawable credits are forced into the `held` bucket and cannot become payout-eligible through a client-supplied `available` status.
- Extended the courier earnings and payout API projections with available, pending, held and withdrawn balances, per-row wallet state, withdrawability and statement categories.
- Added separate order, incentive, adjustment, tax and fee statement totals, including payout fees without rewriting immutable earning rows.
- Preserved and covered the existing database-backed payout idempotency and provider-dispatch idempotency contracts.
- Wired the Android courier wallet/earnings surfaces to render the explicit wallet buckets and statement totals.
- Documented ownership and the boundary between the admin payout ledger and `payment-service` wallet mutation authority.
