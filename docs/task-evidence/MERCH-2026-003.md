## Scope Implemented

- Evolved the existing `merchant_menu_items` source of truth with canonical category, lifecycle, moderation, and version fields rather than creating a duplicate catalog.
- Added normalized category, image, schedule, variant/modifier status, catalog-version, catalog-event, and import records with constraints and compatibility backfill from legacy `kategori`/`foto` values.
- Added server-enforced moderation: new/imported items start `moderation_pending`/`pending`, cannot be made available before approval, and admin approval/rejection records actor, timestamp, and reason. Approval and availability preserve sold-out state when inventory is zero.
- Integrated order-service menu reads and food quote eligibility with canonical status, schedule availability including overnight windows, canonical images, and active variants/modifiers. Existing FOOD-2026-012 stock/sales-limit guards remain authoritative.
- Added durable `merchant.catalog.changed` versioned events to `event_outbox` with `consumer=search-index` and `source_of_truth=merchant-service` for item/category/variant/option/image/schedule changes.
- Added CSV bulk import with 5 MiB/1,000-row limits, per-row validation, duplicate detection, category creation, idempotency request hashing, atomic categories/items/images/import completion, and safe retry/conflict behavior.
- Added the API contract at `docs/contracts/merchant-catalog-governance-2026.md`.
