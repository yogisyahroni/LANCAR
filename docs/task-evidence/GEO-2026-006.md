# Evidence — GEO-2026-006

## Acceptance Criteria Source

## Scope Implemented

- Added deterministic pickup quality evaluation for invalid points, GPS accuracy over 100m, and pin/place divergence over 150m using Haversine distance.
- Customer order creation re-evaluates pickup quality server-side before trusted price calculation and expensive dispatch. Low-confidence or mismatched pickup returns `PICKUP_LOCATION_CORRECTION_REQUIRED` with actionable quality details.
- Browser GPS keeps accuracy on the pickup location/address point and displays a correction prompt for low-confidence GPS. The order form blocks submission until a verified search/saved/manual point is selected; route preview and pricing recalculate from changed form coordinates.
- Added `pickup_location_corrections` audit storage for customer/courier suggestions, including previous/proposed point and address, reason, actor role, status, acceptance actor/time, and route recalculation flag.
- Added authenticated web/mobile customer endpoints plus an assigned-courier suggestion endpoint. Customer acceptance is transactional and locks terminal/picked-up orders.
- Accepting a correction updates only the pre-dispatch order pickup, clears route snapshot/provenance fields, and returns `requires_requote` and `requires_reroute`; the next pricing/dispatch step must obtain a fresh authoritative quote.
- Map matching/quality checks never rewrite the customer's selected point; they only classify it and require an explicit correction flow.
