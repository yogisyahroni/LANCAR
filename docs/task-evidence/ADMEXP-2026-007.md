# Evidence — ADMEXP-2026-007

## Acceptance Criteria Source

The original checklist in `task-food-marketplace-parity-2026.md` requires:

- [x] Admin preview clearly labels this as **post-native-splash campaign intro**, not OS launch splash.
- [x] Admin cannot configure network fetch as a mandatory startup blocker.
- [x] Expired/unavailable asset automatically falls back/skip according to policy.
- [x] Campaign can be scheduled days ahead and assets prefetched before activation.
- [x] Kill action is available to authorized ops/publisher without app release.

## Scope Implemented

- Added a dedicated `campaign_intro` editor branch in the existing App Experience editor with campaign ID/name, localized headline/body fallback and pack keys, primary image/animation asset, linked low-bandwidth fallback asset, dismissible/skippable policy, bounded display/max duration, frequency/impression caps and bounded prefetch window.
- Added an explicit post-native-splash label to both the editor and safe schema preview. The copy states that the campaign never replaces the OS launch splash and cannot make a network request a prerequisite for the first usable screen.
- Extended the existing backend campaign-intro schema with campaign name, duration and prefetch controls. Server validation enforces 1–60 second target display, 1–120 second hard maximum, 1–24 hour prefetch window and `display_duration_seconds <= max_duration_seconds`.
- Reused the existing AssetPicker/asset-reference fallback contract. The customer client verifies the cached local asset, prefers the declared fallback on metered/data-saver networks, and skips the campaign when neither primary nor fallback is valid or when the schedule is expired.
- Applied the configured prefetch window to the audience-scoped Wi-Fi WorkManager policy. The worker remains background/retry work and is not connected to native splash gating. The native campaign layer auto-skips after the bounded target duration so it cannot hold the user indefinitely.
- Kept schedule, market, locale, cohort and app-version controls in the existing manifest editor, so an intro may be scheduled days ahead while only assets inside the safe prefetch window are staged.
- Kept emergency pause/kill on the existing authorized manifest lifecycle. The Admin page exposes Pause/Resume only with the `experience.kill_switch.execute` capability, and published changes take effect through the remote manifest without an app release.
