## Scope Implemented

- Food discovery coordinates are stored separately and are never copied into checkout state.
- Saved receiver addresses use their persisted latitude/longitude.
- Manual address text must be resolved through the existing server-side geocoding endpoint before submit; selecting a result binds its pin to the address.
- Device location is an explicit user action and requires foreground location permission.
- Checkout refuses to create an order when the destination has no explicit valid coordinate.
- Selecting a different destination clears the previous Food quote; checkout requires a fresh server quote before order creation.
- Order service validates address presence, coordinate ranges, finite values, and rejects `0,0` before merchant/order processing.
