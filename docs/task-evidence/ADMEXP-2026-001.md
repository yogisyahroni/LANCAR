# Evidence — ADMEXP-2026-001

## Acceptance Criteria Source

The original checklist in `task-food-marketplace-parity-2026.md` requires:

- Add one clear `APP EXPERIENCE` group under Marketing & Promosi.
- Add protected routes in `App.tsx` for all Experience pages.
- Prevent existing `Banners`, `Promos` and `FeatureFlags` from becoming conflicting parallel sources of truth by reusing, sharing, migrating or redirecting.
- Show the menu according to admin permission and enforce unauthorized access rejection in the backend.
- Keep active market/surface context visible while editing.

## Scope Implemented

- Added one data-driven `APP EXPERIENCE` sidebar group containing all 17 required destinations.
- Added protected routes and a compatibility redirect for the legacy `/app-experience` entry point. Existing pages are wrapped with the shared `ExperienceScopeBar` where they are reused as Experience destinations.
- Kept Promo/Pricing as the financial source of truth, linked Feature Flags to the existing feature-flag store, and made customer Android render legacy `global_banners` only when the resolved Experience manifest has no safe sections. The two presentation sources are never rendered concurrently.
- Added explicit App Experience role enforcement to the Admin feature-flag endpoints and covered denied/read-allowed behavior in the Admin route test.
- Added an accessible market, surface, locale and app-version scope bar. The editor preview supports customer Android, customer Web, merchant Android and courier Android contexts.
