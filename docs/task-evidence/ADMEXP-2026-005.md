# Evidence — ADMEXP-2026-005

## Acceptance Criteria Source

The original checklist in `task-food-marketplace-parity-2026.md` requires:

- [x] Drag/drop reorder produces deterministic ordered schema, not pixel coordinates.
- [x] Admin cannot add arbitrary component names not supported by registered schema.
- [x] Required/safety-critical fallback sections cannot be accidentally deleted when the binary requires them.
- [x] Duplicate/conflicting section IDs rejected.
- [x] Device/app-version preview updates before publish.
- [x] Reordering existing supported components requires no mobile rebuild.

## Scope Implemented

- Added Home Layout mode to the existing App Experience editor at `/app-experience/home-layout`.
- Restricted newly added Home Layout sections to the exact APP-2026-003 initial whitelist: `hero_banner`, `campaign_strip`, `promo_carousel`, `service_grid`, `quick_actions`, `info_card`, `notice` and `spacer`.
- Added HTML drag/drop and keyboard arrow reorder controls. Reorder mutates the manifest `sections` array only, so the persisted contract is deterministic array order rather than pixel coordinates.
- Added per-section ID, component type, enabled state, localized-copy references, CTA/deep-link, asset and safe design-token fields while retaining the existing targeting, schedule, market, surface and app-version fields.
- Added bounded `promo_carousel` item and `quick_actions` editors with presentation-only fields; Promo/Pricing remains authoritative for financial eligibility.
- Prevented removing the final section or disabling the final enabled section in the editor. Backend validation rejects all-disabled manifests, duplicate IDs, invalid enabled types and non-allowlisted components. Android validation also rejects all-disabled remote content and defaults omitted `enabled` to `true` for backward compatibility.
- Connected the preview to enabled sections and the existing audience simulation API. Preview controls include market, locale, app version and cohort, and the preview action is available only for a saved draft.
- Kept reordering wire-compatible with the existing Android renderer; only the optional `enabled` field was added, and Android continues to render the server-provided ordered list without a component-specific rebuild.
