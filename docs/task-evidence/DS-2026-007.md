# Evidence — DS-2026-007

## Acceptance Criteria Source

The original DS-2026-007 checklist in `task-food-marketplace-parity-2026.md` requires:

- [x] Food home can use richer imagery than transactional services without fragmenting core LANCAR typography/spacing/button language.
- [x] Replace emoji fallback with design-system-approved merchant/menu placeholder asset or deterministic neutral placeholder.
- [x] Merchant image/card anatomy uses shared commerce components.
- [x] Sponsored slots are clearly labeled and never indistinguishable from organic ranking.
- [x] Search/filter controls remain sticky/usable without large promotional hero blocking discovery.
- [x] Checkout/payment/tracking surfaces return to calm transaction style and are ad-free.

## Scope Implemented

- Food Home already uses the shared TEMBUS `TembusMerchantCard` and mandatory-disclosure `TembusSponsoredMerchantCard`; DS-2026-007 keeps the richer 4:3 media treatment within the same typography, spacing, badge, and button vocabulary.
- Merchant Detail hero media now uses `TembusCommerceImage`, including deterministic neutral fallback on missing or failed media. Menu rows now use `TembusMenuItemCard`, preserving click/add/availability semantics and bounded text.
- Removed the Merchant Detail local gradient fallback. No emoji or invented food image is used when an API asset is absent.
- Food Home search and halal filters remain outside the scrolling merchant `LazyColumn`, so they stay available while discovery scrolls; no blocking promotional hero is rendered.
- Sponsored selection remains driven by the authoritative Food `is_sponsored` field and the fixed TEMBUS wrapper; merchant `adLabel` cannot replace disclosure. Organic and sponsored cards are structurally distinct in code and visibly labeled.
- Added `validate-food-transaction-surfaces.mjs`, which guards Customer Food Checkout, Payment, Tracking, and Tracking Detail source paths against paid-inventory identifiers. Existing voucher/merchant offers remain transaction-owned, not ad placements.
