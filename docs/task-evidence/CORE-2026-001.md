## Scope Implemented

- Added one canonical category vocabulary: `package_on_demand`, `food`,
  `tambal_ban`, `aggregator`, and `towing`.
- Added a common order contract containing identity, customer, service,
  state/money state, timestamps, actor ownership, quote ID, state version,
  correlation ID, contract version, and degraded-safe service resolution.
- Added typed parcel, food, roadside, aggregator, and towing metadata. Roadside
  metadata can carry structured vehicle/report facts instead of relying on
  `item_description`.
- Added migration/backfill/index/trigger support for canonical order fields.
  Unknown legacy rows remain category-null and degraded rather than being
  assigned a guessed category.
- Preserved legacy flat response fields while exposing `order_contract` and
  `service_metadata` from Admin customer/mobile/web order reads.
- Updated web service presentation to prioritize canonical category and keep
  unknown categories generic; customer Room stores the canonical scalar fields
  through migration 7→8.
- Completed degraded-safe presentation across the remaining surfaces: customer
  Android now has an explicit `UNKNOWN` detail section, courier Android shows
  `LAYANAN BELUM DIKENAL` instead of defaulting to package/regular, Admin uses
  a canonical category display with an explicit unknown label, and customer
  Web order/receipt screens pass the top-level category and contract into the
  shared presenter.
