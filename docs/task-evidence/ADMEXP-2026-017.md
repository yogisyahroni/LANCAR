## Acceptance Criteria Source

- [x] Marketing metrics and reliability metrics are rendered in separate panels and separate table columns; CTR cannot change the reliability status or guardrail calculation.

## Scope Implemented

- Extended the existing canonical Experience observability service with release-dimension breakdowns, safe known-good rollback targets, configurable reliability policy values and policy version metadata. Marketing events remain explicitly excluded from reliability guardrail calculations.
- Added an Admin Overview marketing panel showing impressions, clicks, dismissals and CTR separately from reliability totals, failure rate, fetch latency, startup/network and runtime failure signals.
- Added the health breakdown table with manifest/revision drill links, market/app-version dimensions, reliability rate, fetch latency, marketing counts and an authorized rollback CTA that requires a reason and idempotency key.
- Added `experience_guardrail_policy` to the existing `system_configs` table, a super-admin-only scoped update route with TOTP/idempotency protection, and immutable policy-version increments. Every update is transactionally audited in the existing `audit_logs` table with before/after threshold values.
- Preserved the existing server-side rollback compatibility, checksum/integrity and Experience permission boundaries; the UI is not the security boundary.
