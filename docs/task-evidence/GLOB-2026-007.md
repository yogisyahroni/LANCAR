## Scope Implemented

- Added a canonical, versioned risk decision boundary inside `order-service`, preserving the existing transactional ownership boundary instead of introducing a second order authority or an empty microservice.
- Added governed signal categories for account, device, payment, promo, GPS, handoff, refund, claim, provider, and collusion patterns. Signals have bounded scores, validated codes/sources, coarse allowlisted attributes, and service-generated subject pseudonyms.
- Added the standard `ALLOW`, `CHALLENGE`, `REVIEW`, `HOLD`, and `BLOCK` vocabulary with stable reason codes, policy version, deterministic hard-block rules, and idempotent decision identity.
- Added explicit market/operation policies in `system_configs`. Order and dispatch operations fail open on risk-engine timeout/error; payment, refund, claim, provider callback, payout, and handoff operations default fail closed to `HOLD`. Timeout selection uses `on_timeout`, separately from engine-error policy.
- Wired the risk checkpoint after authoritative quote/voucher/menu-price validation and before order persistence, for both parcel/aggregator and food order creation, and at dispatch start/courier acceptance.
- Added transactional PostgreSQL persistence for decisions and pending manual reviews, including unique operation/idempotency protection, signal snapshot constraints, decision constraints, reviewer/evidence/reason/reviewed-at constraints, and rollback-safe migration.
- Added audited admin review API with bounded filtering/evidence, role and TOTP protection, idempotency-key protection, transactional row locking, reviewer identity, final decision, reason, and evidence recording.
- Added the Admin Web GUI Risk Review queue with pending/resolved filters and the manual resolution form.
- Added the governed `risk.decision` canonical event contract and datalake-worker registry entry. The event carries the decision audit fields and pseudonymous subject hash without raw user/courier identity, exact location, payment credentials, or free-form evidence.
