## Scope Implemented

- Added the Integration Gateway POS capability registry and HTTP adapter for order receipt, catalog sync, inventory sync, and health checks. A provider is only considered acknowledged when it returns an explicit `accepted: true` JSON response; HTTP 2xx alone is not treated as merchant receipt.
- Added durable PostgreSQL delivery/sync state, idempotency keys and request hashes, lease-based retry claiming, immutable integration events, connector health, and reconciliation projections.
- Kept catalog, inventory, pricing, reservations, and customer order acceptance authoritative in LANCAR's existing services. POS sync requests reject non-`lancar` mutation sources with an explicit ownership conflict.
- Kept customer order status `pending_merchant` after both POS failure and POS receipt. Only the existing order-service merchant acceptance transition can move the canonical customer order forward.
- Added authenticated Integration Gateway endpoints for POS order receipt, catalog/inventory sync, health, and reconciliation. Added read-only health/reconciliation projections for the Merchant API and Admin API.
- Added configuration templates for the POS provider URL and API key without adding any secret value to the repository.
