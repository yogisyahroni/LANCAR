## Scope Implemented

- Added `TargetingSummary` to the existing App Experience Audience & Targeting and Scheduling workspaces. It shows the effective audience dimensions, rollout state, schedule timezone, converted admin-local preview, fallback behavior and conflict status.
- Added deterministic Admin-side conflict detection for active published manifests with the same market/surface, overlapping schedule/audience and overlapping enabled placements. It is an early warning; the server resolver remains authoritative.
- Added matching and non-matching preview actions that call the existing server preview endpoint, so both cases are evaluated by the server-side resolver rather than by browser-only rule logic.
- Reused the existing strict server targeting schema/resolver and safe `TargetingEditor`. The public manifest resolver returns the selected sanitized manifest and omits targeting rules; sensitive personal attributes such as email/phone are not accepted by the targeting schema or exposed as UI fields.
- Kept the existing schedule normalization and fallback ranking behavior, and surfaced those semantics in the Admin UI before publish.
