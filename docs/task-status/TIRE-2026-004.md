## Checklist status

- [x] Server-enforced lifecycle.
  - Completion report is accepted only from the assigned roadside technician.
  - Repository locks the order/report path and requires a final-proof-compatible order status before persisting the completion report.
  - Duplicate report submission for the same order resolves idempotently to the already-created report instead of creating a second completion record.
- [x] Before/after proof as configured.
  - Courier inspection flow captures/uploads the before photo and persists the proof draft.
  - Completion screen requires a result photo before the service can be completed.
  - Backend rejects Tambal Ban reports missing either `tire_photo_before_url` or `tire_photo_after_url`.
- [x] Structured material/duration/report.
  - Damage/condition selected during inspection is persisted into the structured draft.
  - Material codes are stored as a structured list, validated server-side, de-duplicated, and encoded for the legacy storage boundary.
  - Service start time is persisted; completion derives a bounded duration and backend requires 1–1440 minutes.
  - Backend also requires condition-before, condition-after, completed-at, and configured proof fields.
- [x] Customer sees human-readable stages.
  - Customer order detail maps Tambal Ban states into labels such as `Mencari Teknisi`, `Teknisi Menuju Lokasi`, `Teknisi Tiba di Lokasi`, `Verifikasi & Inspeksi Ban`, `Ban Sedang Diperbaiki`, `Perbaikan Selesai · Menunggu Bukti Akhir`, and `Layanan Selesai`.
